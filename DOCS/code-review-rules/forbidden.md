# 코드 리뷰 금지 규칙

## 1. 리뷰 방식 금지
- 작성자를 평가하거나 비난하는 표현 금지
- 근거 없는 취향 강요 금지
- "대충 괜찮아 보임" 식의 승인 금지
- 읽지 않은 코드에 대한 승인 금지
- 테스트/운영 영향 확인 없이 핵심 변경 승인 금지

## 2. 이 저장소에서 막아야 하는 변경

### 2.1 인증 구조 위반
- `app` 서비스에서 비밀번호를 다시 검증하는 코드 추가 금지
- `next-auth` 같은 로컬 세션 발급 구조를 재도입하는 변경 금지
- 보호 API에서 클라이언트 전달 `userId`를 그대로 사용하는 변경 금지
- `authUserId` 대신 이메일을 영구 식별자로 고정하는 변경 금지

### 2.2 보안 위반
- JWT secret, OAuth secret, DB 비밀번호를 코드에 하드코딩하는 변경 금지
- 실제 운영 시크릿을 문서 예시에 그대로 남기는 변경 금지
- Refresh Token을 JS 접근 가능한 저장소에 넣는 변경 금지
- 인증서 오류, CORS 오류, 쿠키 정책 오류를 임시 우회로 덮는 변경 금지

### 2.3 데이터 무결성 위반
- 마이그레이션 계획 없이 `User`, `Lesson`, `RefreshToken`, `OAuthAccount` 구조를 깨는 변경 금지
- 이관 계획 없이 `timetable_db.User.password`를 바로 삭제하는 변경 금지
- 기존 계정 매핑 전략 없이 `authUserId` unique 제약만 추가하는 변경 승인 금지

### 2.4 배포/운영 위반
- Docker 컨테이너에서 호스트 DB를 `localhost`로 잡는 변경 승인 금지
- `docker --env-file`에서 따옴표/공백 해석 차이를 무시하는 변경 승인 금지
- `app`과 `auth-server`의 env 규칙을 제각각 두는 변경 승인 금지
- 수동 운영 절차가 필요한데 문서 없이 병합하는 변경 금지

## 3. 리뷰 코멘트 금지 예시
- "이건 왜 이렇게 했죠?"
- "상식적으로 이렇게 하면 안 되죠."
- "그냥 다시 짜세요."
- "테스트는 알아서 하세요."
- "문서까지는 필요 없을 듯"

## 4. 승인 금지 조건
- 인증 우회 가능성이 남아 있음
- 운영 배포가 이미 깨질 가능성이 높음
- 시크릿 노출이 있음
- 주요 리팩토링인데 테스트/검증 근거가 없음
- 문서가 현재 구현과 명백히 다름

## 5. 임시 우회 승인 금지
- "일단 prod에서만 이렇게 쓰고 나중에 고치자"
- "로그인 깨지지만 다음 PR에서 보자"
- "migration 없이 수동으로만 맞추면 된다"

이런 종류의 변경은 단기적으로 빨라 보여도 장기적으로 장애를 만든다. 리뷰 단계에서 막아야 한다.
